title: 'Run a board election'
description: 'Set up a multi-question vote, choose who can vote, publish, close, read and export the results'

This walkthrough runs an end-to-end e-voting session: board elections, by-law changes, motion votes. It uses the [VoteCollection](/api-reference/votecollection), [Vote](/api-reference/vote) and [VoteOption](/api-reference/voteoption) resources.

Who is this for: governance automation that spins up scheduled votes (annual board elections, motion ratification), or integrations that copy vote outcomes back into a federation's records.

Creating and managing votes needs chapter HR rights or being the vote's owner. For admin-side screens, see [E-voting](/platform/e-voting).

---

## Concepts

- A **VoteCollection** is one voting session: one meeting, one ratification cycle, one election. It groups one or more questions.
- A **Vote** is a single question, such as "Elect the treasurer". Each has a `type`: `single` (one option) or `multiple` (several options).
- A **VoteOption** is one answer to a question.
- A ballot is **anonymous** (`isAnonymous: true`) or **attributed** (each ballot is tied to the voter, for votes where the record of who voted how must be kept). Anonymity is chosen up front.
- A member can vote **once**. There is no changing a vote after it is cast.

A collection's `status` is computed, not set by you: `draft`, `upcoming` (published, before `dateStart`), `live` (open now), `closed`, or `empty` (open period over with no votes).

## Step 1: Create the vote collection

```bash
curl -X POST https://acme.orgo.space/api/v1/vote_collections \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Board Election Spring 2026",
    "description": "Cast your vote for three open seats on the Boston chapter board.",
    "dateStart": "2026-03-15T18:00:00+00:00",
    "dateEnd": "2026-03-15T21:00:00+00:00",
    "timezone": "America/New_York",
    "isAnonymous": true,
    "isGeneral": true,
    "unit": "/api/v1/units/4"
  }'
```

The new collection is a draft and comes with one default question and two default answer options, which you rename or extend in step 2. The response includes `totalEligible`, `isEditable`, `status` and `isDraft`.

### Who can vote

The eligible voters follow how the collection is scoped:

| Setup | Who can vote |
|---|---|
| `isGeneral: true` with no `unit` | Members of the organization |
| `isGeneral: true` with a `unit` | Members of that local center, role group or unit |
| `event` set | Attendees of that event |
| Neither (a **private** vote) | Only members the owner added; the owner is added automatically |
| `electorate: "company_voting_representatives"` | The people who were a company's voting representative when the vote started (the list freezes at the start) |

For a private vote, add voters while the collection is still editable, one at a time or in bulk:

```bash
curl -X POST https://acme.orgo.space/api/v1/vote_collections/22/voters \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"userIds": [42, 43, 44]}'
```

The bulk call takes up to 50 members of the organization, skips those already on the list, and returns the number added and the new eligible total. A single voter is `POST /api/v1/vote_users` with `{"voteCollection": "/api/v1/vote_collections/22", "user": "/api/v1/users/42"}`.

### Optional settings

`hideVotersList` hides who has voted from other members. `hasPreliminaryResults` lets voters see running results while the vote is live; otherwise results appear only after it closes.

## Step 2: Add questions and options

```bash
curl -X POST https://acme.orgo.space/api/v1/votes \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "voteCollection": "/api/v1/vote_collections/22",
    "title": "Elect the Boston chapter board for 2026-2027",
    "type": "multiple"
  }'
```

A new question starts with two default options. Add the rest, and rename the defaults with `PATCH /api/v1/vote_options/{id}`:

```bash
curl -X POST https://acme.orgo.space/api/v1/vote_options \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"vote": "/api/v1/votes/45", "title": "James Patterson"}'
```

Repeat for each candidate (Emma Whitfield, Sarah O'Connor, Michael Chen, Olivia Brown). Reorder questions with `PATCH /api/v1/vote_collections/{id}/reorder-questions` and options with `PATCH /api/v1/votes/{id}/reorder-options`.

| Type | Use for |
|---|---|
| `single` | One of many, such as "Approve the budget?" |
| `multiple` | Several selections, such as three board members from five candidates |

There are no ranked-choice or free-text question types.

Questions and options can only be changed while the collection is **editable**: no ballot cast yet, and not yet live or closed. Once voting starts they are locked.

---

## Step 3: Publish

When the questions are in place:

```bash
curl -X PATCH https://acme.orgo.space/api/v1/vote_collections/22/publish \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/merge-patch+json" \
  -d '{}'
```

Publishing checks the dates and scope, then emails the eligible voters and moves the collection to `upcoming` (or straight to `live` if `dateStart` has passed). Publishing twice answers `400 Voting is already published`. Until voting starts you can still edit the collection.

There is no separate "open" call: voting opens by itself at `dateStart`.

---

## Step 4: Members vote

While the collection is `live`, each eligible member casts one ballot that answers **every** question at once:

```bash
curl -X POST https://acme.orgo.space/api/v1/vote_boxes \
  -H "Authorization: Bearer $MEMBER_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "voteCollection": 22,
    "voteOptions": {
      "45": [101, 103, 104]
    }
  }'
```

`voteOptions` maps each question id to the chosen option id (for a `single` question) or a list of option ids (for `multiple`). Leaving a question out answers `400 Please answer all questions`. The ballot is cast as the signed-in member, so this is called with the member's session, not an admin token.

Typical refusals, all `400`: `This voting did not started yet`, `This voting ended`, `You are not eligible for this vote.`, `You are not set as eligible for this vote by the admin.`, and `Already voted`. The answer is a seal (an integrity token over the ballot).

`GET /api/v1/has_live_votes` tells the signed-in member whether there is an open vote they can take part in, which is handy for an "unfinished vote" badge.

## Step 5: Close and read the results

Voting closes by itself at `dateEnd`. To end it early:

```bash
curl -X PATCH https://acme.orgo.space/api/v1/vote_collections/22/close \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/merge-patch+json" \
  -d '{}'
```

The collection must be published and currently open. Results are then available on the collection:

```bash
curl https://acme.orgo.space/api/v1/vote_collections/22 \
  -H "Api-Token: $ORGO_API_TOKEN"
```

```json
{
  "id": 22,
  "status": "closed",
  "hasAvailableResults": true,
  "totalVoted": 142,
  "totalEligible": 312,
  "participationPercentage": 45.5,
  "votes": [
    {
      "id": 45,
      "title": "Elect the Boston chapter board for 2026-2027",
      "type": "multiple",
      "voteOptions": [
        { "id": 101, "title": "James Patterson", "total": 98 },
        { "id": 102, "title": "Emma Whitfield", "total": 87 },
        { "id": 103, "title": "Sarah O'Connor", "total": 76 },
        { "id": 104, "title": "Michael Chen", "total": 54 },
        { "id": 105, "title": "Olivia Brown", "total": 21 }
      ]
    }
  ]
}
```

Counts are raw option totals. Results are only shown (`hasAvailableResults`) after closing, or while live when `hasPreliminaryResults` is on.

For an attributed (non-anonymous) vote, owners can read who voted how: `GET /api/v1/vote_collections/{id}/attributed-results`, and export it with `.../attributed-export`.

---

## Step 6: Export

For board minutes or compliance, export the result set as CSV once the vote has closed:

```bash
curl https://acme.orgo.space/api/v1/vote_collections/22/export \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -o spring-2026-board-election.csv
```

The file lists the questions and answers with the cryptographic seals recorded for audit. Exporting an unfinished vote answers `403 Vote must be finished to export results.` The voter roster (who voted, not how) is `GET /api/v1/vote_collections/{id}/voters-export`.

---

## Step 7: Archive

When the results are circulated and the minutes signed:

```bash
curl -X PATCH https://acme.orgo.space/api/v1/vote_collections/22/archive \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/merge-patch+json" \
  -d '{}'
```

Only a closed collection can be archived. Archived collections stay readable; the list endpoint can filter on them (`isArchived`, or `exists[isArchived]`).

---

## Cloning for the next cycle

To run the same election again, clone instead of rebuilding:

```bash
curl -X PATCH https://acme.orgo.space/api/v1/vote_collections/22/clone \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/merge-patch+json" \
  -d '{}'
```

The clone is a new draft that copies the questions, options and eligible voters, with fresh dates (from now to one hour later) and no results. Update the name, dates and candidates, then publish it as in step 3. For a vote attached to an event, only the event's owner can clone it.

## Common gotchas

<AccordionGroup>
  <Accordion title="The eligible count is lower than expected">
    Eligibility follows the scope table above. For a vote on a local center or group, only members in it count, and only active members. For a private vote, only people on the voter list count. Check `totalEligible` before publishing.
  </Accordion>

  <Accordion title="A voter says they didn't get the notification">
    Publishing emails the eligible voters, so a voter without a usable email address is not reached. They can still vote from the member dashboard while the vote is live.
  </Accordion>

  <Accordion title="Can a member change their vote?">
    No. A ballot is final: a second attempt answers `400 Already voted`. Plan for this in your instructions to voters.
  </Accordion>

  <Accordion title="The vote needs a quorum: how do I enforce it?">
    There is no quorum gate. After closing, compare `totalVoted` with `totalEligible` (or read `participationPercentage`) against your bylaws before treating the result as binding.
  </Accordion>

  <Accordion title="How are ties broken?">
    Orgo reports raw totals. Tie-breaking is a governance decision. For a runoff, clone the collection, keep only the tied candidates, and run it again.
  </Accordion>
</AccordionGroup>
