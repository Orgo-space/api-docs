This walkthrough covers the payment lifecycle as an integration sees it: card payments collected by Stripe and reconciled through webhooks, the parallel invoice flow for bank transfers, offline payments, and refunds. It uses the [ProductPayment](/api-reference/productpayment) and [Invoice](/api-reference/invoice) resources.

Who is this for: finance-ops tools that reconcile Orgo against accounting systems, and backends that react to membership fees, ticket sales and donations.

---

## Architecture

Orgo never touches card data. Stripe collects the card and Orgo records what happened as a `ProductPayment`. Orgo's own checkout surfaces start the Stripe flow: the member fee screens, the public event checkout, donation pages and the company payment checkout. An integration does not create card charges directly. It reads and reacts.

```
1. A buyer pays on an Orgo checkout   (Orgo creates the Stripe session)
2. Stripe confirms the charge          (Orgo records a ProductPayment)
3. Orgo fires product_payment.* webhooks
4. You reconcile                       (CRM, accounting, receipt)
```

The bank-transfer flow is parallel and produces the same downstream event:

```
1. An invoice is issued                (PDF emailed to the payer)
2. The payer sends the transfer        (outside Orgo)
3. An admin marks the invoice paid     (Orgo records a ProductPayment)
4. Orgo fires product_payment.* webhooks, exactly as for a card payment
```

Your reconciliation code can treat both cases identically.

### Statuses and amounts

- Payment statuses are lowercase: `open`, `success`, `refunded`, `canceled`, `pending_accept`.
- Invoice statuses are lowercase: `unpaid`, `paid`, `voided`, `refunded`. Invoice types are `manual_invoice`, `member_renewal` and `event_registration`.
- A payment's `amount` and an invoice's `amount` are in **currency units** (`50.00` is fifty dollars), with a `currency` code alongside.

## Card payments

### Where checkout starts

| Surface | Starts with |
|---|---|
| Event tickets | The public event checkout, see [Build a public event landing page](/api-reference/recipes/build-a-public-event-landing-page) |
| Company membership | `GET /api/v1/companies/{uuid}/payment-checkout`, which creates a Stripe session for the company's selected plan and returns the checkout URL to redirect to. Needs company payment rights or an administrator |
| Member fees, donations | Orgo's fee and donation pages |

```bash
curl https://acme.orgo.space/api/v1/companies/01938d8e-c2f4-7c2a-b8e1-3f7a9b8c4f88/payment-checkout \
  -H "Api-Token: $ORGO_API_TOKEN"
```

Redirect the payer to the URL in the answer. Stripe handles the card. If Stripe is not connected for the organization or center, the call fails; see [Stripe integration](/platform/fees/stripe-integration).

### React through webhooks

Subscribe to the payment events (you need to be an Orgo administrator):

```bash
curl -X POST https://acme.orgo.space/api/v1/webhook_subscriptions \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Payment reconciliation",
    "url": "https://your-app.example.com/webhooks/orgo",
    "eventTypes": ["product_payment.created", "product_payment.updated"],
    "secret": "whsec_a3f8b2c4d6e8f1a3b5c7d9e1f3a5b7c9"
  }'
```

In your handler:

```python
def handle(payload):
    if payload["event"] != "product_payment.updated":
        return
    payment = payload["object"]
    if payment["status"] == "success":
        record_payment_in_accounting(payment)
```

See [Handle webhooks](/api-reference/recipes/handle-webhooks) for the full receiver pattern.

## Recording an offline payment

For cash, a cheque, or a transfer you received outside Orgo, record a completed payment directly. It requires organization-wide finance rights:

```bash
curl -X POST https://acme.orgo.space/api/v1/product-payment/record \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "user": 42,
    "product": "01938d8e-c2f4-7c2a-b8e1-3f7a9b8c4f99",
    "price": 22,
    "amount": 50,
    "paymentDate": "2026-01-15"
  }'
```

Pass exactly one of `user` (a member id) or `contact` (a contact id), `amount`, and either `product` (a product uuid, with an optional price `id`) or `customProductName` for a one-off item. The payment is created as `success` with no Stripe charge. `paymentDate` is optional.

## Refunding a card payment

When a member asks for a refund (cancelled event, mistaken purchase), refund the payment:

```bash
curl -X PATCH https://acme.orgo.space/api/v1/product-payment/107/refund \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/merge-patch+json" \
  -d '{}'
```

Refunds are **full refunds**: the endpoint takes no amount and no reason. It needs finance rights over the payment's center, and only a payment with status `success` can be refunded. The side effects:

- The payment becomes `refunded`.
- Any linked event registrations are canceled, ticket capacity is released and sold counts go down.
- For membership payments, fee validity dates are recalculated.

A payment with no Stripe reference (imported or recorded offline) is only marked refunded, for money you returned outside Orgo. A payment that has an invoice is refunded from the invoice instead (below). For a partial refund, refund in Stripe's dashboard and record the adjustment in your own books.

<Note>
A refund cannot be undone. To charge again, the payer must complete a new checkout.
</Note>

## Bank transfer with an invoice

Two actors can start a bank transfer.

### A member requests an invoice

A signed-in member (any member, no admin rights) asks for a membership renewal invoice with `POST /api/v1/invoices/create-for-bank-transfer`, using their own session. The answer carries the invoice series, amount, currency and the organization's banking details to pay into. A member can have only one pending bank-transfer invoice at a time. The member can withdraw it with `POST /api/v1/invoices/cancel-bank-transfer`, which voids their latest unpaid one (`404` if there is none).

### An administrator issues an invoice

A user with organization-wide admin rights creates a manual invoice, which Orgo numbers, generates as a PDF and emails to the payer immediately:

```bash
curl -X POST https://acme.orgo.space/api/v1/invoices \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "user": "/api/v1/users/42",
    "amount": 50,
    "invoicedFor": "Annual membership 2026",
    "invoiceDate": "2026-01-15",
    "invoiceDueDate": "2026-02-14",
    "billingName": "James Patterson",
    "billingAddress": "123 Beacon Street, Boston, MA 02108",
    "billingEmail": "james.patterson@example.com"
  }'
```

The invoice is created `unpaid` with type `manual_invoice`, a generated `invoiceNumber` and `seriesNumber`, and a download link (`GET /api/v1/invoices/{id}/download`). Use `user`, `contact` or `company` for the payer. For a membership invoice add `isMembership: true`, `membershipProductPrice` and the membership start and end dates, so payment extends the fee period. Billing fields (`billingName`, `billingVatNumber`, `billingEmail`, and so on) are printed on the PDF.

### Mark as paid

When the transfer lands in the bank:

```bash
curl -X PATCH https://acme.orgo.space/api/v1/invoices/284/mark-as-paid \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Content-Type: application/merge-patch+json" \
  -d '{}'
```

This sets the invoice to `paid`, creates a linked `ProductPayment` with status `success`, updates the fee validity of the member or company for membership invoices, confirms the registrations for event invoices, stamps a PAID badge on the invoice and emails the updated copy. Your webhook receiver sees the same `product_payment` events as for a card payment.

### Void, refund and resend

| Action | Endpoint | When to use |
|---|---|---|
| Void | `PATCH /api/v1/invoices/{id}/void` | Issued in error. Also cancels the registrations and the payment of an event invoice |
| Refund | `PATCH /api/v1/invoices/{id}/refund` | A paid invoice must be reversed. **Bookkeeping only**: no money moves through a payment gateway, so return the funds yourself |
| Resend | `GET /api/v1/invoices/{id}/send-email` | The payer's accounts-payable team wants a copy |

All three need organization-wide admin rights. A refund sets the invoice to `refunded`, records who and when, turns the payment into `refunded`, cancels linked event registrations and recomputes fee validity.

## Reporting and reconciliation

### Payments in a date range

```bash
curl "https://acme.orgo.space/api/v1/product_payments?status=success&stripePaymentDate[after]=2026-01-01&stripePaymentDate[before]=2026-01-31&order[stripePaymentDate]=asc" \
  -H "Api-Token: $ORGO_API_TOKEN" \
  -H "Accept: application/ld+json"
```

`hydra:totalItems` gives the count; the array gives the data. Paginate as usual. Other filters: `user`, `contact`, `company`, `product.uuid`, `product.type`, `paymentType`, `amount[gte]`, `amount[lte]`, `exists[isRefunded]`.

### Sum of successful payments

There is no aggregation endpoint. Fetch the pages and sum locally. For monthly reporting that is fine; for dashboards refreshing every minute, cache the result.

### Unpaid invoices past their due date

```bash
curl "https://acme.orgo.space/api/v1/invoices?status=unpaid&order[dateCreated]=asc&itemsPerPage=100" \
  -H "Api-Token: $ORGO_API_TOKEN"
```

Invoices cannot be filtered by due date, so compare `invoiceDueDate` with today on your side to build the dunning list.

## Common gotchas

<AccordionGroup>
  <Accordion title="The checkout fails because no Stripe account is configured">
    Stripe has to be connected for the organization or for the center that owns the product. Check the center's payment settings, see [Stripe integration](/platform/fees/stripe-integration).
  </Accordion>

  <Accordion title="My payment shows success but I never saw the webhook">
    Two usual causes: the subscription was paused (`isActive: false`) at the time, or your receiver returned non-2xx until the attempts ran out. Read `GET /api/v1/webhook_subscriptions/{id}/delivery_logs` and replay from there.
  </Accordion>

  <Accordion title="The refund returned 200 but the cardholder has no money yet">
    Stripe settles refunds over several business days, longer for some cards. The authoritative answer is in Stripe's dashboard.
  </Accordion>

  <Accordion title="The invoice has the wrong VAT: can I edit it?">
    Do not edit a sent invoice. Void it and issue a corrected one. The void keeps the audit trail, and the new invoice gets a new number.
  </Accordion>

  <Accordion title="Can I charge a saved card without redirecting?">
    Not through a general API call. Recurring fees run through the member's subscription, which Stripe bills on its schedule.
  </Accordion>
</AccordionGroup>
