---
title: 'Languages'
description: 'Enable multiple languages so members use Orgo in their preferred language'
---

Orgo's interface is available in multiple languages. You choose which languages are available, set a default, and members pick their preference. The entire interface — menus, buttons, labels, system messages — switches to their language.

---

## Setting up languages

**Settings** → **Customization** → **Languages**

<Steps>
  <Step title="Choose available languages">
    Enable the languages your members need from the supported list.
  </Step>
  <Step title="Set the default">
    Choose the primary language for your organization. New members see this until they change their preference.
  </Step>
  <Step title="Show the language switcher">
    Enable the language selector in the interface so members can switch easily.
  </Step>
</Steps>

---

## Supported languages

| Language | Code |
|----------|------|
| English | en |
| Romanian | ro |
| French | fr |
| German | de |
| Spanish | es |
| Italian | it |
| Portuguese | pt |

The platform interface (menus, buttons, system messages) is fully translated in all supported languages. User-generated content (discussion posts, event descriptions) stays in the language it was written in.

---

## How members choose their language

Members can change their language from their profile menu. The interface updates immediately — no logout required.

For first-time visitors, the system can automatically detect language from:
- Browser language settings
- Previous selection (if they've visited before)

---

## What gets translated

| Content | Translated? |
|---------|------------|
| **Platform interface** (menus, buttons, labels, forms) | Yes — fully translated |
| **System emails** (notifications, confirmations) | Yes — sent in the member's language |
| **User-generated content** (posts, events, files) | No — stays in the original language |
| **Custom labels** (your terminology overrides) | Per-language — you provide translations |
| **Welcome message** | You write separate versions per language |

---

## Multi-language labels

If you've customized labels (e.g., "Members" → "Scouts"), you need to provide translations for each enabled language. See [Labels](/platform/customization/labels) for details.

## Common scenarios

<AccordionGroup>
  <Accordion title="Our organization operates in two languages (e.g., French and German)">
    Enable both languages and set the one with more members as default. Members choose their preference. System emails go out in each member's chosen language. For user content, you may need to post in both languages or use one common language.
  </Accordion>

  <Accordion title="Should I enable all supported languages?">
    Only enable languages your members actually speak. Extra languages just clutter the language picker. You can always add more later.
  </Accordion>

  <Accordion title="A member sees the wrong language">
    They can change it from their profile menu. If new members consistently get the wrong default, check that your default language setting is correct.
  </Accordion>
</AccordionGroup>
